На основе предоставленного учебного пособия (Раздел 5, с. 54–108) подготовлена основная информация по технологии MPI (Message Passing Interface).
------------------------------
## 1. Сущность и архитектура MPI

* Назначение: Общепризнанный стандарт для программирования параллельных вычислительных систем с распределенной памятью (суперкомпьютеров и вычислительных кластеров).
* Базовый принцип: Взаимодействие между параллельными процессами (ветвями) осуществляется исключительно посредством явной отправки и приема сообщений.
* Архитектура реализации (на примере MPICH):
* Служба/демон (spmd): Постоянно работает на каждом узле сети, отвечая за запуск, остановку и обеспечение связи ветвей.
   * Библиотека MPI: Предоставляет интерфейс функций для кода программы.
   * Утилиты: Инструменты запуска (mpiexec, mpirun) и настройки среды.
   * Библиотека MPE: Дополнительное средство сбора статистики и визуализации трассы выполнения (через утилиту Jumpshot-4) для анализа эффективности программы.

## 2. Ключевые понятия MPI

* Коммуникатор: Дескриптор внутренней структуры, определяющий коллектив параллельных ветвей. Любой обмен данными происходит только внутри заданного коммуникатора.
* MPI_COMM_WORLD — автоматически создаваемый коммуникатор, включающий все ветви приложения.
   * MPI_COMM_SELF — содержит только один текущий процесс.
* Ранг (Rank): Уникальный порядковый индекс (номер) процесса внутри коммуникатора (от 0 до size-1).
* Буфер данных: Описывается тремя параметрами: адрес в памяти, длина (количество элементов) и базовый или производный тип данных MPI (например, MPI_INT, MPI_DOUBLE).
* Тэг (Tag): Целочисленный идентификатор сообщения, используемый для того, чтобы приемная сторона не перепутала асинхронно отправленные пакеты.

## 3. Основные группы функций стандарта MPI-1## А. Инициализация и окружение

* MPI_Init(argc, argv) — обязательная инициализация библиотеки (вызывается первой).
* MPI_Finalize() — обязательное корректное завершение работы MPI во всех ветвях.
* MPI_Comm_size(comm, &size) — возвращает общее число процессов в коммуникаторе.
* MPI_Comm_rank(comm, &rank) — возвращает ранг текущего процесса.

## Б. Обмен «точка-точка» (Point-to-Point)
Обеспечивает передачу сообщений между парой процессов. Бывает блокирующим (процесс ждет окончания операции) и неблокирующим (обозначается префиксом I — Immediate, возвращает дескриптор квитанции MPI_Request для контроля окончания операции через MPI_Wait или MPI_Test).

* Базовая пара: MPI_Send (блокирующая отправка) и MPI_Recv (блокирующий прием).
* Режимы отправки: Стандартная (MPI_Send), синхронная (MPI_Ssend — ждет начала приема), буферизованная (MPI_Bsend — копирует в системный буфер) и по готовности (MPI_Rsend — требует, чтобы прием уже был инициирован).
* Совмещенные функции: MPI_Sendrecv и MPI_Sendrecv_replace (одновременный прием и передача для каскадных схем).

## В. Коллективные операции
Вызываются обязательно всеми ветвями коммуникатора одновременно в блокирующем режиме:

* MPI_Barrier — барьерная синхронизация (все процессы ждут, пока каждый не дойдет до этой точки).
* MPI_Bcast — широковещательная рассылка данных от одного процесса всем остальным.
* MPI_Scatter / MPI_Scatterv — блочное разрезание и распределение частей одного массива по всем процессам.
* MPI_Gather / MPI_Gatherv — сбор порций данных со всех процессов в один результирующий массив.
* MPI_Allgather / MPI_Alltoall — сбор и обмен данными «все со всеми».
* MPI_Reduce — операция глобальной редукции (свертки). Применяет математическую операцию (MPI_SUM, MPI_MAX, MPI_MIN и др.) к переменным на всех процессах и собирает результат на одном. MPI_Allreduce рассылает результат редукции всем процессам.

## Г. Производные типы данных и упаковка
Позволяют передавать структуры или несмежные элементы памяти (например, столбцы матриц) без лишних накладных расходов:

* Конструкторы типов: непрерывный (MPI_Type_contiguous), векторный с постоянным шагом (MPI_Type_vector), структурный (MPI_Type_create_struct — самый универсальный) и др.
* Требуют обязательной регистрации через MPI_Type_commit перед использованием и удаления через MPI_Type_free.
* Альтернативный механизм — явная побайтовая упаковка/распаковка через MPI_Pack / MPI_Unpack.

## Д. Топологии
Позволяют логически упорядочить процессы для упрощения адресации соседей. Поддерживаются декартовы топологии (прямоугольные сетки, решетки, торы через MPI_Cart_create) и графы (MPI_Graph_create).
------------------------------
## 4. Новые возможности стандарта MPI-2

* Динамическое порождение процессов: Возможность запускать новые вычислительные ветви (процессы-потомки) прямо во время работы программы с помощью функции MPI_Comm_spawn или MPI_Comm_spawn_multiple.
* Удаленный доступ к памяти (RMA — Remote Memory Access): Реализует концепцию односторонних взаимодействий, когда один процесс (инициатор) может напрямую читать (MPI_Get) или записывать (MPI_Put, MPI_Accumulate) данные в память другого процесса (адресата) без его явного участия. Для этого предварительно коллективно создается выделенное «окно» памяти через MPI_Win_create. Синхронизация RMA осуществляется с помощью коллективного забора (MPI_Win_fence) или блокировок (MPI_Win_lock/MPI_Win_unlock).
* Параллельный ввод/вывод (MPI-IO): Совместный параллельный доступ группы процессов к одному файлу (тип данных MPI_File). Каждый процесс может настраивать свой собственный «вид файла» (MPI_File_set_view) через элементарные типы (e-тип) и файловые типы, определяя, какие именно порции глобального файла ему видны. Чтение и запись поддерживают позиционирование по явным смещениям, индивидуальным или общим указателям, в блокирующей, неблокирующей или разделенной коллективной формах.
