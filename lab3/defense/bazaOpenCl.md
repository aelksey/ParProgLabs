# Теоретическая база OpenCL (Краткий конспект для защиты)

## 1. Что такое OpenCL и зачем он нужен?

**OpenCL (Open Computing Language)** — это открытый стандарт для **гетерогенного параллельного программирования**. Он позволяет писать один код, который без перекомпиляции может выполняться на совершенно разных вычислительных устройствах: центральных процессорах (CPU), графических ускорителях (GPU), сигнальных процессорах (DSP) или программируемых логических матрицах (FPGA).

### Главное отличие от CUDA:
* **NVIDIA CUDA** — это закрытая, проприетарная технология. Код CUDA физически работает *только* на видеокартах NVIDIA.
* **OpenCL** — кроссплатформенный стандарт. Ваша лабораторная работа успешно доказала это на практике: один и тот же исходный код запустился и на домашней видеокарте **AMD Radeon RX 580**, и на серверной видеокарте **NVIDIA Quadro 5000**.

## 2. Архитектурные модели OpenCL

Стандарт OpenCL жестко разделяет вычислительную систему на несколько абстрактных моделей. На защите нужно уметь назвать четыре базовые модели:

### А. Платформенная модель (Platform Model)
Описывает роли устройств в системе. Всегда делится на две части:
* **Хост (Host):** Управляющий компьютер (процессор CPU под управлением ОС Windows/Linux). Он выполняет основной код программы (`main.c`), координирует ресурсы и раздает задачи.
* **Устройства (Devices):** Вычислительные ускорители (в нашем случае дискретная видеокарта GPU). Устройство состоит из одного или нескольких **вычислительных ядер (Compute Units)**, которые, в свою очередь, делятся на **обработки элементов (Processing Elements)**.

### Б. Модель выполнения (Execution Model)
Описывает, как именно параллельный код выполняется на видеокарте.
* **Хост-программа:** Управляет контекстом, создает очереди команд и отправляет данные.
* **Ядро (Kernel):** Специальная функция (код `kernel.cl`), написанная на языке OpenCL C. Она компилируется прямо во время работы (JIT) и запускается в виде огромной сетки потоков.
* **Иерархия потоков (NDRange):** 
  * **Work-item (Исполнительный элемент / Поток):** Одиночный поток, выполняющий одну копию ядра (один пиксель или одна координата матрицы).
  * **Work-group (Рабочая группа / Блок потоков):** Группа потоков, которая выполняется на одном вычислительном блоке GPU. Потоки внутри одной группы могут синхронизироваться между собой и использовать общую быструю локальную память. В нашей программе размер группы задан флагом `-g 16` (плитки $16 \times 16$).

### В. Модель памяти (Memory Model)
Память в OpenCL строго разделена по уровням доступа. Это важно, так как у GPU нет прямого доступа к оперативной памяти компьютера (ОЗУ):

1. **Глобальная память (Global Memory):** Самая большая память видеокарты (видеопамять VRAM, например 8 ГБ у RX 580). Доступна для чтения и записи **всем** потокам на GPU. Она медленная (по меркам GPU), именно в неё мы загружаем исходную матрицу.
2. **Константная память (Constant Memory):** Часть глобальной памяти, защищенная от записи. Используется для неизменяемых аргументов.
3. **Локальная память (Local Memory):** Сверхбыстрая память, общая для потоков **внутри одной конкретной Work-group** (аналог Shared Memory в CUDA). Другие группы её не видят.
4. **Приватная память (Private Memory):** Самая быстрая память (регистры конкретного ядра). Доступна **только одному конкретному потоку** (`Work-item`). В ней хранятся локальные переменные потока (например, счетчики циклов `i`, `j` и промежуточная сумма `current_sum`).

### Г. Модель программирования (Programming Model)
Описывает характер параллелизма. OpenCL поддерживает два типа:
* **Параллелизм по данным (Data Parallel):** Наш случай. Одно и то же ядро одновременно применяется к миллионам разных элементов данных (каждый поток считает свою координату матрицы).
* **Параллелизм по задачам (Task Parallel):** В очередь отправляются разные независимые функции, выполняющиеся параллельно.

## 3. Основные термины OpenCL, которые нужно знать наизусть

* **Контекст (`cl_context`):** Виртуальное пространство, внутри которого происходят все вычисления. Объединяет видеокарту, её память, очереди команд и скомпилированные программы.
* **Очередь команд (`cl_command_queue`):** Буфер, через который Host отправляет команды на GPU. Команды бывают трех типов: выполнение ядер (`clEnqueueNDRangeKernel`), копирование памяти на GPU (`clCreateBuffer`) и чтение памяти обратно на CPU (`clEnqueueReadBuffer`).
* **JIT-компиляция (Just-In-Time):** Компиляция исходного кода ядра из текстового файла непосредственно при запуске программы. Это позволяет драйверу видеокарты оптимизировать машинный код под конкретную модель GPU, которая установлена в системе прямо сейчас (будь то AMD Polaris или NVIDIA Fermi).
* **Редукция данных (Reduction):** Процесс свертки огромного массива данных в одно итоговое значение. В вашей работе GPU выдал плоский массив из миллионов сумм, а CPU выполнил редукцию — пробежался по ним и нашел один единственный абсолютный минимум.
