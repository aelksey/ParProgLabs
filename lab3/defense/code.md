# Реализация параллелизма и руководство по функциям OpenCL

## 1. Концепция распараллеливания задачи (Как мы делим работу?)

В последовательной версии на CPU один поток выполняет два тяжелых вложенных цикла, сдвигая окно поиска по строкам и столбцам:
$$\text{CPU: } \underbrace{\text{for (r = 0...)}}_{\text{Строки}} \rightarrow \underbrace{\text{for (c = 0...)}}_{\text{Столбцы}} \rightarrow \text{Вычисление суммы треугольника}$$

В технологии OpenCL мы **полностью избавляемся от этих двух внешних циклов**, перекладывая их выполнение на аппаратную сетку потоков GPU. 

### Принцип деления работы:
1. **Двухмерная сетка (NDRange):** Мы создаем виртуальную двухмерную сетку потоков (`global_size`), где по оси `X` находятся столбцы матрицы, а по оси `Y` — строки.
2. **Один поток — одна координата:** Видеокарта аппаратно и одновременно порождает миллионы независимых вычислительных элементов (Work-items). Каждый такой элемент (поток) «знает» свое уникальное место на сетке.
3. **Изолированное вычисление:** Поток с координатами `(c, r)` мгновенно вычисляет сумму нижнего треугольника, беря элемент `matrix[r * cols + c]` в качестве его левой верхней вершины.
4. **Сверхбыстрая запись:** Все потоки пишут свои результаты одновременно в разные ячейки одного большого плоского массива `sum_results` в видеопамяти. Потоки не пересекаются и не блокируют друг друга, так как адрес записи индивидуален: `linear_idx = r * padded_cols + c`.

## 2. Пошаговое объяснение ключевых функций OpenCL в хост-коде (`opencl_runner.c`)

Для управления видеокартой со стороны центрального процессора используется стандартный конвейер инициализации OpenCL API.

### Шаг 1: Поиск платформ и устройств
```c
err = clGetPlatformIDs(10, platforms, &num_platforms);
err = clGetDeviceIDs(platforms[i], CL_DEVICE_TYPE_GPU, 1, &device, NULL);
```
* **`clGetPlatformIDs`** — запрашивает список доступных в системе драйверов (платформ) OpenCL (например, *NVIDIA CUDA*, *AMD ROCm*, *Intel OpenCL*). 
* **`clGetDeviceIDs`** — опрашивает конкретную платформу и ищет внутри нее физические вычислительные устройства заданного типа (`CL_DEVICE_TYPE_GPU` — дискретные видеокарты, `CL_DEVICE_TYPE_CPU` — центральный процессор в качестве ускорителя). В нашем коде реализован умный цикл, который перебирает все платформы, пока гарантированно не захватит видеокарту сервера (*NVIDIA Quadro 5000*).

### Шаг 2: Создание среды окружения и канала команд
```c
context = clCreateContext(NULL, 1, &device, NULL, NULL, &err);
queue = clCreateCommandQueue(context, device, 0, &err);
```
* **`clCreateContext`** — создает изолированное вычислительное пространство (контекст). Оно объединяет выбранное устройство, его внутреннюю память и управляет общими ресурсами.
* **`clCreateCommandQueue`** — открывает очередь (канал) команд для отправки задач на GPU. Видеокарта выполняет операции (копирование памяти, запуск вычислений) асинхронно, считывая их из этой очереди по порядку.

### Шаг 3: Компиляция ядра «на лету» (JIT-компиляция)
```c
program = clCreateProgramWithSource(context, 1, (const char**)&kernel_src, NULL, &err);
err = clBuildProgram(program, 1, &device, NULL, NULL, NULL);
kernel = clCreateKernel(program, "find_min_triangle", &err);
```
* **`clCreateProgramWithSource`** — загружает текстовый исходный код из файла `kernel.cl` в объект программы OpenCL внутри контекста.
* **`clBuildProgram`** — запускает встроенный в видеокарту компилятор. Он транслирует высокоуровневый Си-подобный код ядра в низкоуровневый бинарный машинный код (ассемблер) конкретной архитектуры GPU сервера.
* **`clCreateKernel`** — извлекает из скомпилированной программы конкретную функцию-ядро (`find_min_triangle`) для последующего запуска.

### Шаг 4: Выделение и привязка памяти
```c
d_matrix = clCreateBuffer(context, CL_MEM_READ_ONLY | CL_MEM_COPY_HOST_PTR, size, matrix, &err);
clSetKernelArg(kernel, 0, sizeof(cl_mem), &d_matrix);
```
* **`clCreateBuffer`** — выделяет физический блок памяти прямо в высокоскоростной VRAM (видеопамяти) видеокарты. Флаг `CL_MEM_COPY_HOST_PTR` заставляет OpenCL не просто выделить память, но и сразу скопировать туда исходную матрицу из ОЗУ хоста.
* **`clSetKernelArg`** — устанавливает аргументы для функции-ядра. Мы связываем указатели на буферы памяти и обычные переменные (`rows`, `cols`, `tri_size`) с аргументами, которые ожидает увидеть функция в `kernel.cl`.

### Шаг 5: Постановка задачи в очередь и чтение результатов
```c
clEnqueueNDRangeKernel(queue, kernel, 2, NULL, global_size, local_size, 0, NULL, NULL);
clFinish(queue);
clEnqueueReadBuffer(queue, d_res_sum, CL_TRUE, 0, size, h_res_sum, 0, NULL, NULL);
```
* **`clEnqueueNDRangeKernel`** — отправляет ядро на исполнение на аппаратную сетку. Параметр `2` указывает, что сетка двухмерная. `global_size` задает общее число потоков по осям, а `local_size` разбивает их на блоки (Work-groups).
* **`clFinish`** — блокирует выполнение программы на CPU и заставляет хост дождаться момента, пока GPU полностью очистит очередь команд и завершит все миллиарды математических операций.
* **`clEnqueueReadBuffer`** — скачивает рассчитанные массивы результатов из видеопамяти обратно в оперативную память хоста для последующей финальной редукции и записи отчета. Флаг `CL_TRUE` делает это чтение синхронным (блокирующим).

## 3. Комментарии и разбор кода параллельного ядра (`kernel.cl`)

Ниже представлен детальный разбор внутренней логики кода, который выполняется на каждом ядре GPU:

```c
__kernel void find_min_triangle(
    __global const int* matrix, // Указатель на исходную матрицу в глобальной видеопамяти
    int rows, int cols,         // Реальные размеры матрицы
    int tri_size,               // Размер искомого подтреугольника S
    __global int* row_results,  // Выходной массив строк для каждого потока
    __global int* col_results,  // Выходной массив столбцов для каждого потока
    __global ulong* sum_results) // Выходной массив вычисленных сумм (64 бита)
{
    // Аппаратное получение координат текущего потока в двухмерной сетке
    int c = get_global_id(0); // Ось X: уникальный номер столбца (сдвиг по горизонтали)
    int r = get_global_id(1); // Ось Y: уникальный номер строки (сдвиг по вертикали)
    
    // Получаем реальную ширину расширенной (padded) сетки потоков
    int padded_cols = get_global_size(0);
    // Вычисляем уникальный плоский индекс потока для записи в линейные массивы
    int linear_idx = r * padded_cols + c;

    // ГЕОМЕТРИЧЕСКИЙ БАРЬЕР: Проверяем, помещается ли треугольник в границы матрицы.
    // Координаты вершины должны быть >= 0, а нижний и правый края треугольника 
    // не должны вываливаться за пределы физических габаритов (rows и cols)
    if (r >= 0 && r + tri_size <= rows && c >= 0 && c + tri_size <= cols) {
        ulong current_sum = 0; // Локальный 64-битный регистр потока для накопления суммы
        
        // Поэлементный обход компактного нижнего треугольника
        for (int i = 0; i < tri_size; i++) {
            // Рассчитываем смещение строки в памяти с приведением к ulong во избежание переполнения
            ulong row_offset = (ulong)(r + i) * (ulong)cols;
            
            // Внутренний цикл обхода столбцов подматрицы.
            // Условие j <= i — КЛЮЧЕВОЙ МОМЕНТ ЗАДАЧИ: оно отсекает элементы выше диагонали,
            // заставляя поток суммировать исключительно нижнетреугольную область.
            for (int j = 0; j <= i; j++) {
                current_sum += (ulong)matrix[row_offset + (ulong)(c + j)];
            }
        }
        
        // Запись результатов вычисления текущего потока в глобальную память хоста
        row_results[linear_idx] = r;
        col_results[linear_idx] = c;
        sum_results[linear_idx] = current_sum;
    } 
    else {
        // Если поток попал в область дополнения (padding) или треугольник не влезает:
        // Пишем максимальное значение (0xFFFFFFFFFFFFFFFFUL = ULONG_MAX),
        // чтобы этот поток гарантированно проиграл при финальном поиске минимума.
        sum_results[linear_idx] = 0xFFFFFFFFFFFFFFFFUL;
        row_results[linear_idx] = -1; // Маркер невалидности координаты строки
        col_results[linear_idx] = -1; // Маркер невалидности координаты столбца
    }
}
```
