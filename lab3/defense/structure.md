## Архитектурная структура и описание модулей проекта

Разработанное программное решение декомпозировано на **4 модуля исходного кода на языке C** (реализующих логику управления, работы с диском и вычислений на CPU) и **1 модуль параллельного ядра на языке OpenCL C** (выполняемый непосредственно на графическом процессоре). 

Ниже приведено подробное описание назначения и функционала каждого файла проекта:

### 1. Заголовочный файл `common.h`
Данный файл является связующим звеном всего проекта. Он не содержит исполняемого кода, а выполняет декларативную функцию:
* **Подключение OpenCL API:** Интегрирует базовые системные заголовочные файлы консорциума Khronos (`<CL/cl.h>`).
* **Определение структуры `AppArgs`:** Описывает типы данных для хранения параметров конфигурации, переданных через командную строку (путь к файлу матрицы, размер треугольника \(s\) и размер локальной рабочей группы \(g\)).
* **Прототипы функций:** Объявляет сигнатуры общих служебных методов и вычислительных модулей (`run_sequential` и `run_parallel`). Это обеспечивает строгую типизацию и позволяет компилятору `gcc` безопасно связывать объектные файлы между собой на этапе линковки.

### 2. Главный управляющий модуль `main.c`
Файл содержит функцию `main()` и является координатором всего вычислительного эксперимента:
* **Интерфейс командной строки (CLI):** Реализует разбор Unix-style параметров запуска и автоматически выводит структурированную справку (`--help`) при некорректном вводе.
* **Файловый ввод-вывод (I/O):** Открывает внешний текстовый файл матрицы, валидирует корректность заголовка размерности (`rows` \(\times\) `cols`), динамически выделяет память в ОЗУ хоста и осуществляет потоковое чтение элементов.
* **Профилирование и бенчмаркинг:** Поочередно запускает последовательный и параллельный алгоритмы, фиксируя чистое время выполнения каждого блока без учета накладных расходов на дисковые операции.
* **Многокритериальная верификация:** Выполняет пошаговое сравнение результатов (контроль совпадения абсолютных минимумов, счетчиков количества найденных экстремумов и побитовое равенство извлеченных треугольных подматриц). По окончании выводит псевдографическую таблицу в консоль и генерирует итоговый объемный отчет `submatrix_output.txt`.

### 3. Модуль CPU-логики и утилит `utils.c`
Содержит служебную инфраструктуру хоста и эталонную реализацию алгоритма:
* **Функция `get_time_sec`:** Использует системные таймеры POSIX (`clock_gettime` с флагом `CLOCK_MONOTONIC`) для измерения временных интервалов с наносекундной точностью, полностью исключая влияние корректировок системного времени.
* **Функция `load_kernel_source`:** Осуществляет чтение текстового файла `kernel.cl` с диска и преобразует его в динамическую строку в памяти для последующей передачи JIT-компилятору.
* **Функция `run_sequential`:** Реализует классическое последовательное решение задачи на CPU. Посредством вложенных циклов выполняет лексикографический обход матрицы, вычисляет суммы элементов нижних компактных треугольников, определяет глобальный минимум, подсчитывает число его дубликатов и сохраняет структуру элементов самой последней найденной оптимальной подматрицы.

### 4. Диспетчер параллельного рантайма `opencl_runner.c`
Данный модуль полностью управляет аппаратным ускорителем (на сервере инициализируется профессиональная видеокарта **NVIDIA Quadro 5000**) через вызовы низкоуровневого API OpenCL:
* **Гетерогенная инициализация:** Опрашивает сервер, динамически перебирает все доступные платформы OpenCL и захватывает физическое GPU-устройство, изолируя вычислительный контекст (`clCreateContext`) и очередь команд (`clCreateCommandQueue`).
* **Runtime-компиляция:** Передает исходный код ядра драйверу NVIDIA для JIT-компиляции «на лету» под конкретную микроархитектуру GPU. Реализует перехват лога компилятора (`CL_PROGRAM_BUILD_LOG`) для вывода синтаксических ошибок в консоль разработчика.
* **Менеджмент видеопамяти:** Создает буферы в памяти видеокарты (`clCreateBuffer`) со строгим контролем соответствия 32-битных и 64-bit типов данных между ОС Linux и GPU. Копирует исходную матрицу на устройство, вычисляет расширенную двухмерную сетку потоков (`global_size`), кратную локальным блокам (`local_size`), и отправляет ядро на исполнение.
* **Хост-редукция:** Вычитывает рассчитанные массивы сумм и координат обратно в ОЗУ и осуществляет финальный поиск глобальных экстремумов в порядке обхода, идентичном CPU.

### 5. Параллельное ядро `kernel.cl`
Программа, написанная на языке **OpenCL C**, компилируемая JIT-компилятором видеокарты и аппаратно выполняемая параллельно тысячами независимых вычислительных ядер GPU:
* **Двухмерная адресация:** Каждый независимый поток (`Work-item`) с помощью функций `get_global_id(0)` и `get_global_id(1)` определяет свою уникальную координату (столбец `c` и строку `r`) на плоскости матрицы.
* **Параллельное суммирование:** Поток проверяет, помещается ли искомый треугольник в границы родительской матрицы начиная с данной позиции. Если условие выполняется, поток осуществляет быстрый локальный обход ячеек нижнего компактного треугольника (где индекс столбца не превышает текущий индекс строки внутри локального блока: `j <= i`) и записывает полученную 64-битную сумму (`ulong`) в плоский глобальный массив по индексу `linear_idx`.
* **Фильтрация подсеток:** Если геометрически треугольник выходит за рамки матрицы, поток мгновенно завершается, записывая в таблицу результатов маркеры невалидности (`-1` для координат и максимальное число `0xFFFFFFFFFFFFFFFFUL` для суммы), предотвращая порчу валидных данных.

### Схема взаимодействия компонентов системы

```text
[ Текстовый файл матрицы ]
           │
           ▼ (чтение заголовка и элементов)
      [ main.c ] ─────────────────────────┐
           │                              │
           ▼ (вызов CPU версии)           ▼ (вызов OpenCL версии)
     [ utils.c ]                     [ opencl_runner.c ]
     (Последовательный                    │  (инициализация Quadro 5000)
      перебор матрицы)                    ▼
           │                         [ kernel.cl ]
           │                         (Параллельный просчет всех
           │                          координат в видеопамяти GPU)
           │                              │
           ▼ (возврат минимумов)          ▼ (выгрузка результатов)
      [ main.c ] <────────────────────────┘
           │
           ▼ (сравнение сумм, счетчиков и структур подматриц)
+-------------------------------------------------------+

|  1. Вывод сводного бенчмарка в консоль (SUCCESS)       |
|  2. Дамп извлеченных элементов в submatrix_output.txt |
+-------------------------------------------------------+
```
