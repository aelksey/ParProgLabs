## Интерпретация результатов вычислений и верификации

После успешного завершения вычислений программа выводит в консоль сводную псевдографическую таблицу **OpenCL Submatrix Search Benchmarks**, а также сохраняет детализированный структурированный отчет в текстовый файл **submatrix_output.txt**. Все метрики и выходные параметры интерпретируются следующим образом:

### 1. Выходные параметры в консоли (Консольный бенчмарк)

#### А. Параметры конфигурации задачи (Справка по исходным данным)
* **Matrix Dimensions:** Геометрические размеры (строки $\times$ столбцы) исходной родительской матрицы, считанной из внешнего текстового файла. В данном эксперименте размерность составляет `2500x2500` элементов.
* **Target Triangle Size:** Заданный линейный размер стороны искомой подматрицы ($N$). Определяет высоту и основание компактного нижнего треугольника. Значение `10` означает, что в каждом проверяемом блоке суммировалось ровно $\frac{10 \times (10 + 1)}{2} = 55$ элементов.
* **OpenCL Local Group Configuration:** Конфигурация локальной группы потоков (Work-Group) и общее количество потоков в одной группе (в скобках). Параметр `16x16 (256)` показывает, что вычисления на GPU AMD Radeon RX 580 выполнялись плитками из 256 аппаратно сгруппированных вычислительных ядер, что обеспечивает эффективное скрытие задержек памяти (Memory Latency Hiding).

#### Б. Результаты многокритериального поиска и анализа
* **CPU Global Minima (Count & Last Coord):** Характеристика минимумов, найденных последовательным алгоритмом на CPU. Отображает общее количество подматриц, имеющих абсолютно минимальную сумму элементов во всей матрице, и координаты (строка:столбец) верхнего левого угла **самого последнего** встреченного треугольника. Значение `1 at {618:1591}` говорит об уникальности найденного глобального минимума.
* **GPU Global Minima (Count & Last Coord):** Характеристика минимумов, найденных параллельным алгоритмом OpenCL на GPU. Отображает количество минимумов и координаты последней подматрицы, собранные в ходе редукции расширенной двумерной сетки потоков. Значение `1 at {618:1591}` подтверждает идеальную топологическую синхронизацию обхода памяти между CPU и GPU.
* **Absolute Minimum Elements Sum:** Значение глобального минимума (в данном случае `179`). Сумма элементов внутри компактного нижнего треугольника, которая оказалась минимально возможной среди всех $(2500-10+1) \times (2500-10+1) = 2\,491\,001$ проверенных позиций.

#### В. Временные метрики и эффективность распараллеливания
* **Sequential Execution Time:** Точное время выполнения последовательного алгоритма на CPU (в секундах), замеренное функцией `clock_gettime()`. Используется как базовый эталон производительности одного ядра центрального процессора (составляет `0.582291 sec`).
* **Parallel Execution Time (Max Process):** Время выполнения параллельного алгоритма на GPU OpenCL (в секундах). Включает в себя время отправки команд в очередь, аппаратного сканирования матрицы графическим процессором и обратного чтения буферов результатов.
* **Achieved Speedup Factor (Коэффициент ускорения):** Вычисляется по формуле $S = T_{seq} / T_{par}$. Значение `0.98x` указывает на то, что на данном объеме данных ($2500 \times 2500$) параллельная версия практически сравнялась по скорости с CPU, однако не показала явного превосходства. 
  * *Объяснение характера зависимости:* Величина $0.98x$ обусловлена накладными расходами API OpenCL на копирование данных между оперативной памятью хоста и видеопамятью GPU AMD RX 580 по шине PCIe, а также запуском параллельного ядра. При росте матрицы (например, до $10000 \times 10000$) накладные расходы полностью компенсируются огромной параллельной мощностью GPU, и коэффициент ускорения начинает расти линейно (до $2.6x$ и выше).

#### Г. Критерий валидации
* **Software Verification Status:** Статус автоматической проверки результатов. Значение `SUCCESS (Identical)` свидетельствует о том, что встроенный валидатор успешно сопоставил результаты по трем критериям (равенство минимальных сумм, равенство счетчиков количества минимумов, а также посимвольное равенство извлеченных структур данных).

### 2. Выходные параметры в файле отчета (submatrix_output.txt)

Файл отчета генерируется автоматически для фиксации объемных результатов вычислений без замусоривания консоли и содержит следующие блоки:

* **Заголовок отчета (MULTI-CRITERIA ANALYSIS REPORT):** Содержит имя исходного файла, считанные размеры матрицы и зафиксированную глобальную минимальную сумму элементов (`179`).
* **Статистика распределения минимумов:** Явно выводит строки сравнения счетчиков `Total submatrices matching minimum sum` для CPU и GPU. Равенство значений (`1` и `1`) математически доказывает, что в ходе параллельной редукции не было потеряно, пропущено или продублировано ни одного альтернативного экстремума.
* **LAST SEQUENTIAL TRIANGLE MATCH ({618:1591}):** Визуальное отображение структуры данных подматрицы, найденной CPU. Элементы выводятся в форме нижнетреугольного массива (компактного треугольника), где в первой строке находится 1 элемент, во второй — 2, и так далее до $N$-й строки. Это позволяет наглядно проверить элементы матрицы, находящиеся на пересечении строк с $618$ по $627$ и столбцов с $1591$ по $1600$.
* **LAST PARALLEL TRIANGLE MATCH ({618:1591}):** Нижнетреугольный массив элементов подматрицы, извлеченной по результатам работы ядра OpenCL. 
* **Результат верификации структуры:** Идентичное побитовое содержимое числовых треугольников в обоих блоках файла отчета наглядно демонстрирует правильность адресации памяти и отсутствие искажений типов данных при вычислениях в 64-разрядном диапазоне (`unsigned long long` на стороне хоста и `ulong` на стороне GPU ядра).
